# JUNGOL [8551_STL Sort 1]
https://jungol.co.kr/problem/8551
- 제한: 시간 2초 / 메모리 1024MB
- 분류: 정렬 (STL 문법 Tutorial)
- 풀이 날짜: 2026-11-04

## 문제 요약
N개의 정수 배열에서 x번 ~ y번 칸만 정렬한 결과와, 배열 전체를 정렬한 결과를 출력한다. (N ≤ 100,000)

## 접근 방법
1. N이 최대 10만이라 O(N²) 정렬(선택·삽입·버블)은 시간 초과이므로 내장 정렬(O(N log N))을 쓴다
2. x ~ y는 끝을 포함하는 구간이고 슬라이싱은 끝을 포함하지 않으므로 `a[x:y+1]`로 자른다
3. 슬라이스는 새 리스트(복사본)라서, 정렬 결과를 `a[x:y+1] = sorted(a[x:y+1])`로 원본에 다시 대입한다
4. 이어서 `a.sort()`로 전체를 정렬한다 (부분 정렬 여부와 관계없이 전체 정렬 결과는 같음)

## 복잡도
- 시간: O(N log N)
- 공간: O(N)

# 공부 노트

## 1. `map`

### 정체
- `map(함수, 반복가능객체)`: 각 원소에 함수를 적용하는 **이터레이터**
- 배열이 아니다. 값을 저장해두지 않고 요청받을 때 하나씩 계산한다 (지연 평가)
- 첫 번째 인수는 **자료형이 아니라 함수**다. `int`는 `int("10") → 10`처럼 변환 함수로 호출되는 것

```python
list(map(int, ["1", "2", "3"]))         # [1, 2, 3]
list(map(abs, [-3, 5, -7]))             # [3, 5, 7]
list(map(str.upper, ["a", "b"]))        # ['A', 'B']
list(map(lambda v: v * 2, [1, 2, 3]))   # [2, 4, 6]
```

### 왜 list에 바로 넣지 않고 map을 거치나
- `input().split()`의 결과는 **문자열 리스트**
- 문자열 상태로 정렬하면 사전 순 비교라서 숫자 크기대로 정렬되지 않는다

```python
sorted("10 5 7 2".split())     # ['10', '2', '5', '7']  ← 오답
sorted(map(int, "10 5 7 2".split()))   # [2, 5, 7, 10]
```

- 같은 결과의 다른 표현: `[int(s) for s in input().split()]`

### map vs list

| 항목 | list | map 객체 |
|---|---|---|
| 정체 | 값을 다 담은 컨테이너 | 값을 하나씩 만드는 이터레이터 |
| 인덱스 접근 | 가능 | 불가 |
| `len()` | 가능 | 불가 |
| 여러 번 순회 | 가능 | 한 번만 (다 쓰면 소진) |
| 메모리 | 원소 수만큼 | 거의 안 씀 |

```python
m = map(int, ["1", "2", "3"])
print(m)         # <map object at 0x...>
print(list(m))   # [1, 2, 3]
print(list(m))   # []  ← 이미 소진

x, y = map(int, input().split())   # 값 2개는 list 없이 바로 언패킹 가능
```

## 2. 파이썬 list와 C 배열 (메모리)

### C 배열이 길이를 미리 정하는 이유
- 컴파일러가 메모리를 고정 크기로 미리 확보해야 한다
- `A[i]`의 주소 = 시작주소 + i × 4. 같은 크기 칸이 빈틈없이 붙어 있어야 계산이 성립하고, 그래서 빠르다
- 배열이 자기 길이를 저장하지 않는다. 범위 밖 접근을 막아주지 않는 대신 오버헤드가 없다
- 크기를 바꾸려면 `malloc`/`realloc`으로 직접 관리해야 한다

### 파이썬 list가 길이를 안 정해도 되는 이유
- 내부적으로 **동적 배열**: 포인터 배열 + 현재 개수(size) + 확보한 칸 수(capacity)
- 칸이 다 차면 인터프리터가 더 큰 메모리를 잡고 옮긴다. 여유분을 두고 늘려서 `append`는 평균 O(1)
- 안 쓰는 메모리는 참조 카운팅·가비지 컬렉터가 자동 회수

| 항목 | C 배열 | 파이썬 list |
|---|---|---|
| 크기 | 생성 시 고정 | 자동으로 늘어남 |
| 메모리 관리 | 컴파일러 / 프로그래머 | 인터프리터 자동 |
| 칸에 든 것 | 값 자체 (int 4바이트) | 객체 주소 (8바이트) + 별도 정수 객체 |
| 자료형 섞기 | 불가 | 가능 |
| 길이 정보 | 없음 | 있음 (`len()` O(1)) |
| 장점 | 빠르고 메모리 효율적 | 편하고 안전 |

- C++ `vector`, Java `ArrayList`도 같은 동적 배열 방식이다
- 인덱스로 바로 값을 넣어야 하면 파이썬도 미리 만든다: `dp = [0] * (n + 1)`

## 3. 슬라이싱은 복사다

- 파이썬 list 슬라이싱은 원본을 가리키는 것이 아니라 **새 리스트를 만든다 (얕은 복사)**

```python
a = [10, 5, 7, 4, 8]
b = a[1:4]       # [5, 7, 4]
b[0] = 999
print(a)         # [10, 5, 7, 4, 8]  ← 원본 그대로
print(a is b)    # False
```

- **대입문 왼쪽의 슬라이스는 다르다**: `a[1:4] = [...]`는 원본의 그 구간을 교체한다
- **얕은 복사**라서 리스트 안의 리스트는 공유된다

```python
a = [[1], [2]]
b = a[:]           # 리스트 전체 복사 관용구
b[0].append(9)
print(a)           # [[1, 9], [2]]  ← 내부 리스트는 공유
```

- 비교: C++ `sort(A + x, A + y + 1)`의 `A + x`는 원본을 가리키는 포인터라 원본을 직접 정렬한다. NumPy 배열 슬라이싱도 원본을 가리키는 view를 반환한다

### 메모리 흐름 (예제 1: x=1, y=4)
```
a              : [10, 5, 7, 4, 8, 2, 6, 8, 5]
a[1:5]         : [5, 7, 4, 8]        ← 새 리스트 (임시)
sorted(a[1:5]) : [4, 5, 7, 8]        ← 또 다른 새 리스트 (임시)
a[1:5] = ...   : [10, 4, 5, 7, 8, 2, 6, 8, 5]   ← a는 같은 객체, 1~4번만 교체
a.sort()       : [2, 4, 5, 5, 6, 7, 8, 8, 10]   ← a는 같은 객체, 제자리 정렬
```

## 4. `.sort()` vs `sorted()`

| 항목 | `a.sort()` | `sorted(a)` |
|---|---|---|
| 종류 | 리스트 메서드 | 내장 함수 |
| 대상 | 리스트만 | 순회 가능한 모든 것 (튜플, 문자열, 집합, map 등) |
| 원본 | 바뀜 (제자리 정렬) | 그대로 |
| 반환값 | `None` | 정렬된 새 리스트 |
| 추가 메모리 | 거의 없음 | 새 리스트만큼 |
| 옵션 | `key`, `reverse` | `key`, `reverse` |
| 알고리즘 | Timsort, O(N log N), 안정 정렬 | 동일 |

### `sorted()`의 동작
1. 괄호 안이 먼저 계산된다 (`a[1:5]` → 새 리스트)
2. 그 객체의 참조가 `sorted`에 전달된다 (값을 통째로 복사해서 넘기는 게 아님)
3. `sorted`가 원소를 순회해 자기만의 새 리스트를 만들고, 정렬해서 반환한다

```python
scores = [72, 95, 88, 60, 91]
top3 = sorted(scores, reverse=True)[:3]
print(*top3)     # 95 91 88
print(*scores)   # 72 95 88 60 91  ← 원본 순서 유지

sorted((3, 1, 2))   # [1, 2, 3]  튜플도 가능, 결과는 항상 리스트
sorted("banana")    # ['a', 'a', 'a', 'b', 'n', 'n']
```

- 원본이 필요 없으면 `.sort()`, 원본을 지켜야 하거나 리스트가 아니면 `sorted()`

## 5. 언패킹 연산자 `*`, `**`

### `*` : 순서 있는 값들 펼치기 / 모으기
```python
a = [3, 1, 2]
print(*a)              # print(3, 1, 2) → 3 1 2
print(*a, sep=",")     # 3,1,2

first, *rest = [10, 20, 30, 40]    # first=10, rest=[20, 30, 40]
*front, last = [10, 20, 30, 40]    # front=[10, 20, 30], last=40

merged = [*[1, 2], *[3, 4]]        # [1, 2, 3, 4]

def total(*args):                  # 위치 인자들을 튜플로 모음
    return sum(args)
```

### `**` : 딕셔너리(키-값) 펼치기 / 모으기
```python
opts = {"sep": "-", "end": "!\n"}
print(1, 2, 3, **opts)              # 1-2-3!

d = {**{"a": 1}, **{"b": 2}}        # {'a': 1, 'b': 2}

def f(**kwargs):                    # 키워드 인자들을 딕셔너리로 모음
    print(kwargs)
```

### `*` 없는 언패킹
```python
x, y = map(int, input().split())
x, y = y, x      # swap
```

### 헷갈리지 말 것
- `3 * 4` 곱셈, `[0] * 5` 리스트 반복, `2 ** 10` 거듭제곱
- 값 사이에 있으면 연산, 값 앞에 붙으면 언패킹

## 6. 자주 틀리는 코드

| 잘못된 코드 | 결과 | 이유 |
|---|---|---|
| `a[x:y+1].sort()` | `a` 그대로 | 복사본만 정렬되고 버려짐 |
| `a = a.sort()` | `a`가 `None` | `.sort()`의 반환값은 `None` |
| `sorted(a)` 한 줄만 | 변화 없음 | 반환된 새 리스트를 저장하지 않음 |
| `a[x:y] = sorted(a[x:y])` | A[y] 빠짐 | 슬라이싱은 끝 인덱스 미포함 |
| `print(a)` | `[2, 4, ...]` | 대괄호·쉼표까지 출력되어 오답 |
| 문자열 입력에 `.rstrip()` 누락 | 길이 +1 | `readline`이 `\n`까지 읽음 |
