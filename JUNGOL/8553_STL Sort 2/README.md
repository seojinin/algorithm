## 문제 요약
N개의 세 자리 정수를 1순위 일의 자리, 2순위 십의 자리, 3순위 백의 자리 숫자 기준으로 오름차순 정렬해 출력한다. (N ≤ 100,000)

## 풀이 파일
| 파일 | 방식 |
|---|---|
| [solution_cmp.py](<./solution_cmp.py>) | 두 원소를 비교하는 comp 함수 + `cmp_to_key` |
| [solution_key.py](<./solution_key.py>) | 원소마다 우선순위 튜플을 만드는 key 함수 |

## 접근 방법
1. N이 최대 10만이므로 내장 정렬(O(N log N))을 쓴다
2. 각 자리 숫자는 일의 자리 `x % 10`, 십의 자리 `x // 10 % 10`, 백의 자리 `x // 100`으로 구한다 (세 자리 수가 보장되므로 백의 자리는 `x // 100`으로 충분)
3. comp 방식: 1순위가 다르면 바로 결론을 내고, 같으면 다음 순위로 넘어간다. 결과를 음수 / 0 / 양수로 반환하고 `cmp_to_key`로 감싸서 key로 넘긴다
4. key 방식: `(일의 자리, 십의 자리, 백의 자리)` 튜플을 key로 쓴다. 튜플은 앞 원소부터 비교하므로 1순위 → 2순위 → 3순위 정렬이 한 번에 된다
5. 출력이 최대 10만 줄이라 `print`를 반복하지 않고 `'\n'.join(map(str, a))`로 한 번에 출력한다

## 복잡도
- 시간: O(N log N)
- 공간: O(N)

# 공부 노트

## 1. 비교 함수(comp)와 `cmp_to_key`

### 반환값 규칙
- 정렬 기준상 left가 앞이면 **음수**, 같으면 **0**, 뒤면 **양수**
- "앞이다"는 숫자 크기가 아니라 **내가 정한 기준**에서의 순서다
- 예: `comp(991, 123)` → 991이 더 크지만 일의 자리 1 < 3이라 991이 앞 → **-1**

### C++ comp와 차이

| 항목 | C++ | Python |
|---|---|---|
| 반환값 | `true` / `false` (Left가 앞이면 `true`) | 음수 / 0 / 양수 |
| 같은 값일 때 | `false` | `0` |
| sort에 넘기는 법 | `sort(A, A + N, comp)` | `a.sort(key=cmp_to_key(comp))` |

- `sort`는 `key`만 받기 때문에, 두 원소를 비교하는 함수는 `cmp_to_key`로 감싸서 key로 바꿔 넘긴다

## 2. key 함수와 튜플 비교

- key 함수는 원소 하나를 받아 **정렬에 쓸 값**을 돌려준다. 정렬은 원소 대신 이 값끼리 비교한다
- 튜플은 **앞 원소부터** 비교한다. 앞이 다르면 거기서 결론, 같으면 다음 원소로 넘어간다

```python
(1, 9) < (2, 0)        # True  첫 원소에서 결론
(1, 2, 3) < (1, 2, 4)  # True  세 번째 원소에서 결론
```

- 그래서 "1순위가 같을 때만 2순위를 본다"는 규칙을 튜플 하나로 표현할 수 있다
- `key=priority`와 `key=lambda x: (...)`는 같은 코드다. 함수에 이름을 붙였는지만 다르다

## 3. comp vs key

| 항목 | comp + `cmp_to_key` | key |
|---|---|---|
| 비교 방식 | 두 원소를 직접 비교 | 원소마다 key를 만들어 비교 |
| 함수 호출 | 비교할 때마다 | 원소마다 한 번 |
| 실행 시간 (N = 10만) | 약 0.32초 | 약 0.10초 |
| 쓰는 경우 | 튜플로 표현하기 어려운 기준 | 기준을 튜플로 표현할 수 있을 때 (대부분) |

- 원리를 익히기엔 comp, 실전에서는 key를 주로 쓴다

## 4. 축약: `x % 100`, `x` 자체로 비교하기

- 2순위: 일의 자리가 같은 수끼리는 `x % 100`(아래 두 자리) 비교 = 십의 자리 비교
  - `x % 100 = 십의 자리 × 10 + 일의 자리`인데 일의 자리가 같으므로 십의 자리만 차이를 만든다
- 3순위: 아래 두 자리가 같은 수끼리는 `x` 자체 비교 = 백의 자리 비교
- 100~999의 모든 두 수 조합(81만 쌍)에서 원래 방식과 결과가 같다

```python
def priority(x):
    return (x % 10, x % 100, x)   # (x % 10, x // 10 % 10, x // 100)과 결과 같음
```

- **주의:** 앞 순위가 같다는 전제에 기대는 축약이다. "1순위 십의 자리, 2순위 일의 자리"처럼 순위 순서가 바뀌면 성립하지 않는다
- 그래서 문제 문장과 일대일로 대응하는 각 자리 추출 방식을 기본으로 썼다

## 5. 처음 떠올린 방식: 묶어서 정렬하고 합치기

### 방식
1. 일의 자리로 전체 정렬
2. 일의 자리가 같은 묶음끼리 십의 자리로 정렬
3. 아래 두 자리가 같은 묶음끼리 백의 자리로 정렬
4. 묶음을 합쳐서 출력

### 평가
- 정답이 나오고 시간 복잡도도 O(N log N)으로 같다 (묶음별 정렬의 합 Σ gᵢ log gᵢ ≤ N log N)
- 다만 정렬을 여러 번 하고 묶음 경계를 직접 찾아야 해서 코드가 길고 실수하기 쉽다
- 정렬 부분만 재면 약 68ms로 튜플 key(약 47ms)보다 조금 느리다
- `sort`는 묶고 합치지 않는다. 두 원소를 비교할 때마다 튜플을 앞에서부터 비교해서 같은 결과를 낸다

### 전체 정렬을 여러 번 하려면 낮은 순위부터
- Python `sort`는 **안정 정렬**이라 key가 같은 원소는 원래 순서를 유지한다
- 그래서 3순위 → 2순위 → 1순위 순서로 전체를 정렬하면 마지막 기준이 1순위가 된다

```python
a.sort()                             # 3순위
a.sort(key=lambda x: x // 10 % 10)   # 2순위
a.sort(key=lambda x: x % 10)         # 1순위
```

## 6. 값의 범위가 작으면: 계수 정렬

- 이 문제는 값이 100~999로 900가지뿐이라, 비교 정렬 없이 **개수를 세서** 정렬할 수 있다

```python
cnt = [0] * 1000
for _ in range(n):
    cnt[int(input())] += 1
order = sorted(range(100, 1000), key=lambda x: (x % 10, x // 10 % 10, x // 100))
out = []
for v in order:
    out += [v] * cnt[v]
```

- 시간 복잡도 O(N + K), K = 900. 실측 약 0.05초 (튜플 key 약 0.10초)
- 값의 범위가 클 때(예: 10억)는 배열을 만들 수 없어서 쓸 수 없다
- "값의 범위가 작다"는 조건이 보이면 떠올릴 수 있는 방법

## 7. 자주 틀리는 코드

| 잘못된 코드 | 결과 | 이유 |
|---|---|---|
| comp에서 `return 0` 누락 | `TypeError` | 같은 값일 때 `None`이 반환됨 |
| comp가 `True` / `False` 반환 | 정렬 결과가 틀림 | Python은 음수 / 0 / 양수 규칙. `True`는 1(뒤), `False`는 0(같음)으로 처리됨 |
| `a.sort(key=comp)` | `TypeError` | key 함수는 인자를 하나만 받음. `cmp_to_key(comp)`로 감싸야 함 |
| 십의 자리를 `x // 100`으로 계산 | 정렬 결과가 틀림 | `x // 100`은 백의 자리. 십의 자리는 `x // 10 % 10` |
| 1순위부터 전체를 여러 번 정렬 | 마지막 기준으로만 정렬됨 | 여러 번 정렬하려면 낮은 순위부터 |
| 한 줄에 하나씩 입력인데 `input().split()` | 첫 수만 읽음 | 수마다 `input()`을 따로 호출해야 함 |
